# Дані, файли та збереження

Основні типи визначені в [`entities.ts`](../src/types/entities.ts). Серіалізатори — у [`projectDirectoryService.ts`](../src/services/project/projectDirectoryService.ts) та [`projectFileService.ts`](../src/services/project/projectFileService.ts). Не використовуйте приклади документації як заміну цим контрактам.

## Сутності

| Тип | Зміст |
| --- | --- |
| `ProjectState` | ID, назва, тип проєкту, словники ресурсів, Dataset та налаштування |
| `SourceImage` | Початковий blob, ім’я, розміри, шляхи, tags та необов’язкові ознаки |
| `EditedAsset` | Результат редагування, PNG/blob і необов’язковий PSD, зв’язок із джерелом |
| `Dataset` | Налаштування спільного набору та порядок; не авторитетний список фізичних членів |
| `WorkspaceImage` | Проєкція source/edited/file-ресурсів для інструментів, включно з PSD і відео |

Тип проєкту — `character`, `style` або `concept`. Профілі в `projectProfiles.ts` задають тексти та початкові налаштування; зараз усі три типи дозволяють повний набір інструментів. Для старого проєкту без типу потрібен явний вибір, невідомий тип відхиляється.

## Папка проєкту

```text
project-folder/
  manifest.json
  dataset/
  src/
    shared/
    assets/
  .cache/
    previews/
  .git/
    dataset-creator-versions.json   # після створення версій
    snapshots/                    # ZIP-знімки версій
```

`projectLayoutService.ts` визначає обов’язкові директорії. Приклад показує ролі папок, а не повний список файлів.

- `manifest.json` — формат `dataset-creator-directory`; читач підтримує версії 1 і 2. Тут зберігаються метадані проєкту, налаштування та посилання на ресурсні маніфести.
- `dataset/` — фізичний фінальний набір. Додавання переміщує сюди ресурс; вилучення переміщує в `src/shared/`. Членство не визначається старими прапорцями виключення.
- `src/shared/` — спільні матеріали й кандидати для доповнення Dataset. `src/assets/` — інші ресурси проєкту.
- Супровідні `<ім’я-файлу>.manifest.json` зберігають метадані ресурсів. TXT містить підпис, який можна імпортувати або експортувати разом із зображенням.
- `.cache/previews/` містить відновлювані прев’ю, а не оригінали.
- `.git/` використовується застосунком для власного індексу та ZIP-знімків. Це не реалізація звичайних Git-комітів або синхронізації з GitHub.

Explorer використовує логічний префікс `Project/`, наприклад `Project/dataset/portrait.png`; це не додаткова фізична папка. Нормалізацію й перенесення шляхів виконуйте через наявні helpers, не через довільні заміни рядків.

## Підписи та членство

Поточний resolver бере `tags`, якщо поле визначене, навіть коли це `[]`. Лише відсутність tags дозволяє fallback із тексту. Для аналізу підпис нормалізується окремо; нормалізований текст не слід записувати назад замість авторського підпису.

Старі `assetIds`, `assetPaths`, `psdAssetPaths`, `captionOverrides`, `overwriteCaptions`, `*.dataset.json` і `dataset.json` зустрічаються у читачах та міграціях. Їх не потрібно повертати в новий UI як паралельний механізм членства або підписів. Під час відкриття старої папки міграція може записувати зміни; це не суто read-only операція.

## Три види стану

| Сховище | Що містить | Обмеження |
| --- | --- | --- |
| Папка проєкту | Файли, маніфести, версії | Потрібен доступ на читання/запис; помилки запису не означають успішного збереження |
| IndexedDB | Дані ресурсів, кеші, handles тегера; окрема БД відео | Може бути очищена браузером; не замінює копію проєкту |
| localStorage | Workspace, вкладки, докування, UI-параметри | Не є резервною копією зображень |

Основна IndexedDB — `DatasetCreator`, схема 3; перелік stores міститься в `constants.ts`. Відеокеш — `dataset-creator-video-frames-v1` зі stores `frames`, `thumbnails`, `meta`. Workspace snapshot має ключ `dataset-creator-workspace-v2`; старі ключі читаються для міграції.

Blob URL живе лише в поточній сесії. Він не є шляхом до файлу і має звільнятися після заміни або завершення використання. Для довготривалого збереження потрібні bytes і метадані, а не URL.

## Версії та архіви

Versions зберігає іменовані ZIP-знімки та зв’язок із батьківською версією. Відновлення змінює файли поточної папки; UI має враховувати незбережені документи та помилки відновлення. Не плутайте це з Undo/Redo окремої дії.

`projectFileService.ts` також підтримує архівний формат `.dcproj`. Наявність цього сервісу не означає, що основний UI відкриття папки використовує архів. Для міграції архіву без project type потрібні resolver типу та writable handle оригінального архіву.

# Посібник користувача

Інтерфейс повністю англійською; цей посібник називає елементи так, як вони підписані в застосунку. Є один інтерфейс із двома екранами: **Projects** (початковий) і **Board** (робочий). Параметри адреси `?ui=` і `?tool=` ігноруються.

## Projects: створення та відкриття

Запустіть застосунок за [інструкцією встановлення](../README.md). Для роботи з локальною папкою браузер має підтримувати File System Access API. Якщо вибір папки недоступний, перевірте браузер і те, що застосунок відкритий через localhost або HTTPS.

Екран **Projects** має два блоки.

- **Recent projects** — недавні папки проєктів, найновіші змінені першими (до 12; найстаріші випадають). Рядок показує назву, тип і модель, час останньої зміни, кількість кадрів у Dataset і стан доступу (**Ready**, **Needs access**, **No access**). Клік відкриває проєкт; за потреби застосунок запитує в браузера доступ на запис. Кнопка з хрестиком прибирає запис зі списку, не чіпаючи папку. **Open folder…** відкриває будь-яку папку вручну.
- **New project** — назва, **Type** (Character, Style, Concept or object, General; типово Character) і **Model** (SD 1.5, SDXL, Flux; типово SDXL, поруч показано мінімальну коротшу сторону). Кнопка **Choose folder and create** просить вибрати папку, у якій буде створено проєкт.

Тип задає початкові налаштування, пояснення та набір осей покриття в Health; модель визначає мінімальну коротшу сторону (512 px для SD 1.5, 1024 px для SDXL і Flux). Обидва значення можна змінити пізніше в Project settings. Старий проєкт без типу відкривається як General без запитів і без переписування файлу; для відкриття проєкту старого формату див. «Старі проєкти».

Якщо відкрити папку без проєкту, застосунок попросить підтвердження перед створенням проєкту та запитає назву, тип і модель. Файли, перейменовані чи переміщені поза застосунком, розпізнаються за вмістом (SHA-256); зовнішня зміна вмісту робить уже прийняте рішення застарілим (stale). Справжній Git-репозиторій у папці захищено від змін. Кнопка **Projects** у шапці Board повертає до списку.

### Структура папки

Деталі — у [моделі даних](data-model.md). Коротко: сирі матеріали лежать у `inbox/` (підпапки дозволені), у `dataset/` — лише пари зображення + `<ім’я>.txt` (підпапки на кшталт `10_name/` дозволені), `exports/` містить ZIP експорту, а службові дані — `.datasetcreator/`. Вміст `dataset/` готовий для kohya або OneTrainer без перетворень. Підпис — це TXT: немає файлу — підпису немає, порожній файл — порожній підпис; у `dataset/` TXT починається з trigger word.

### Старі проєкти

Проєкт старого формату (v2/v1) відкривається через діалог **Upgrade project layout** із переліком змін. Перед змінами записується знімок версії, замінені файли копіюються в `.datasetcreator/backup`, а перервана міграція продовжується при наступному відкритті. Якщо оновлення заблоковано незавершеною старою міграцією, діалог пропонує **Open without upgrading**: проєкт відкриється у старому вигляді, а оновлення запропонують знову пізніше. Рішення старої сесії Build переносяться один раз: пропущене зображення стає **Banned**, прийняте вручну — **Pinned**; решту статусів застосунок обчислює сам (див. модель даних).

Статус у нижній частині екрана показує збереження: відрізняє тимчасову сесію від збереження в папку. Якщо папку не підключено, не вважайте дані на диску збереженими. Помилка автозбереження потребує повторної спроби після відновлення доступу (**Ctrl/Cmd + S** або команда **Save project**).

## Board

Board — єдине робоче місце від матеріалів до експорту. Шапка зліва направо: **Projects**; назва проєкту (клік перейменовує); чіп «тип · модель · min N px» (відкриває Project settings); перемикач **Select / Caption**; керування Assemble; **Versions**; **Settings**. У режимі Select є три колонки: **Sources**, сітка кадрів і **Health**; у режимі Caption — картки підписів і статистика тегів.

### Sources

Ліва колонка показує дерево папок `inbox/` із кількістю зображень у кожній і підсумок: **Inbox**, **Ticked sources**, **Dataset**.

- **Додавання.** Перетягніть файли чи папки на рядок папки (або на всю колонку — тоді вони потрапляють у корінь `inbox/`); **Add files** і **Add folder** імпортують у вибрану папку, **New folder** створює підпапку всередині вибраної. Імпорт приймає зображення BMP/GIF/JPEG/PNG/WebP, PSD, відео MP4/WebM, TXT і JSON; підписи TXT зіставляються із зображеннями за базовим ім’ям у межах папки й лишаються поруч із ними. Однакові імена в різних папках не є однією парою. Великий імпорт зберігається пакетами (до 25 файлів або 250 мс).
- **Галочка біля папки** — «бере участь в Assemble» (Use this folder when assembling); галочка папки охоплює її підпапки, часткове позначення показано проміжним станом. Якщо жодних джерел не вибирали, вважається, що позначено весь `inbox/`; папки, додані пізніше, автоматично не позначаються. Вибір зберігається в проєкті (`profile.sources`).
- **Переміщення.** Папку чи кадри з сітки можна перетягнути на іншу папку `inbox/`; ім’я файлу зберігається, посилання, джерела й «звідки зображення» оновлюються. Папку не можна перемістити в саму себе чи її підпапку.
- **Перейменування папки** — олівець, подвійний клік або F2; Enter підтверджує, Escape скасовує. **Видалення папки** — кошик; перед видаленням застосунок просить підтвердження, папка зникає і з вибраних джерел. Корінь `inbox/` не можна ні перейменувати, ні видалити.
- **Відео** не є кадрами: вони лишаються поза сіткою й лічильниками, але перелічені під деревом (див. «Відеокадри»).

### Сітка й статуси

Кожен кадр має один статус; колір ніколи не єдиний його носій — є текст і значок.

| Статус | Значення |
| --- | --- |
| **In** | Файл лежить у `dataset/`. Підказка пояснює, наприклад: найкращий у групі, скільки схожих кадрів лишилось поза набором |
| **Pinned** | In, закріплений вами: лишається в Dataset при повторному Assemble |
| **Out** | Не в Dataset. Причини: **Quality** (не пройшов перевірку якості; наводяться підстави), **Duplicate of …** (з відсотком схожості) або «Not selected» (Assemble лишив кадри, що краще покривають набір) |
| **Banned** | Заблокований вами: ніколи не потрапляє в Dataset |
| **Inbox** | Ще чекає: «Waiting for Assemble», «Not analyzed yet» або відео, з якого треба вирізати кадри |

Статус пояснюється підказкою на плитці й у lightbox. Кадри, що не в Dataset, а також Out і Banned, показано приглушено. Група `dataset` завжди йде першою, далі — папки за назвою.

Фільтри **All / In / Out / Pinned / Banned** показують лічильники; фільтр «In» охоплює і Pinned. Окремого фільтра для Inbox немає. Фільтр з Health (див. нижче) діє поверх цих фільтрів і показується позначкою «Showing: …» з хрестиком.

Кнопка **Themes / Folders** з’являється, коли після Assemble пораховано кластери: **Themes** групує кадри за тематичними кластерами (чи групами повторів, якщо Strictness теми не дає), **Folders** — за папками; типово — Themes. Сітка віртуалізована: мініатюри існують лише для видимого вікна.

Керування: клік по плитці відкриває lightbox; **Ctrl/Cmd або Shift + клік**, а також галочка в куті плитки вибирають кілька кадрів; стрілки, Home та End переміщують курсор. Для вибраних кадрів з’являється панель дій: **Pin**, **Ban**, **Clear override**, **Return to inbox** і **Delete files** (див. нижче). Позначка «N selected · Clear» скидає вибір; вибір, прихований фільтром, не враховується.

### Assemble

Assemble автоматично відбирає кадри з позначених Sources у Dataset. Він сам запускає перевірку якості (окремого ручного кроку немає) і працює лише за явною дією.

- **Size** — **Auto** (типово для нових проєктів): з кожної групи схожих кадрів лишається один; цільова кількість не обмежує добір. **Target** — поле «Target images» задає цільовий розмір Dataset (закріплені кадри та вже наявні в `dataset/` рахуються); якщо кандидатів більше потрібного й підключено локальну модель підписів, вона описує кадри для звуження вибору. Старі сесії без цього поля читаються як Target.
- **Strictness** (**Strict / Balanced / Loose**) — наскільки схожими мають бути два кадри, щоб вважатися однією групою. Це налаштування проєкту; воно також доступне в Settings. Різні рівні дають різні групи, тому Loose зливає ширші групи, а Strict — вужчі.
- **Assemble dataset** запускає добір. Під час роботи замість елементів керування показано етап (**Checking quality**, **Understanding images**, **Comparing images**, **Choosing the best of each group**, **Adding to the dataset**), прогрес і кнопку **Cancel**; скасування лишає проєкт як був. Якщо потрібна модель DINOv2 (≈88 MB), застосунок пропонує завантаження й чекає підтвердження: мовчки вона не завантажується.
- Кнопка недоступна, поки жодна папка Sources із зображеннями не позначена.
- Результат — рядок над сіткою: кількість зображень і груп, скільки додано, скільки дублікатів і скільки відхилено за якістю. Лічильники записує сам конвеєр. Далі замість кнопки з’являється **Re-assemble**, а також **Export N pairs** (кнопка Export видима, поки в Dataset є кадри).
- Assemble за один прохід додає кадри й записує пояснення для решти (причини Out). Закріплені кадри лишаються в Dataset, заблоковані не беруть участі. Повторний Assemble без змін нічого не додає й не рухає.
- **Один Undo.** Увесь Assemble — один крок історії: **Ctrl/Cmd + Z** повертає кадри в inbox і Health — до початкового пояснення.

### Pin, Ban та інші дії над кадром

Єдиний статус, який задає користувач, — Pin або Ban; решту обчислює застосунок. Дії працюють з вибраними кадрами, а без вибору — з кадром під курсором; кожна — один крок Undo.

| Дія | Що відбувається |
| --- | --- |
| **Pin** (**P**) | Кадр одразу переміщується в `dataset/` і лишається там при повторному Assemble. Відео закріпити не можна |
| **Unpin** (**P** ще раз) | Знімає закріплення, не переміщуючи файл |
| **Ban** (**B**) | Кадр ніколи не потрапляє в Dataset; якщо він був у `dataset/`, повертається в папку, звідки прийшов |
| **Unban** (**B** ще раз) | Знімає блокування |
| **Remove from dataset** | Так у lightbox називається **Ban** для кадра з `dataset/`: він іде назад в inbox і стає Banned |
| **Clear override** | Знімає Pin або Ban, не рухаючи файли (є в панелі дій над вибраними) |
| **Return to inbox** | Забирає кадр із Dataset без блокування; Pin при цьому знімається, Ban лишається |

Клавіші **P** і **B** перемикають дію: якщо всі цільові кадри вже мають її, друге натискання знімає її. Вони не спрацьовують, коли фокус у текстовому полі. Повернення з Dataset іде в папку `inbox/`, з якої кадр прийшов; якщо її вже немає — у корінь `inbox/`.

**Delete** (кадр у lightbox або **Delete files** над вибраними) видаляє файли лише з `inbox/`, після підтвердження; кадри `dataset/` так не видаляються — спершу поверніть їх в inbox. Видалення файлів не слід плутати з поверненням у Sources.

### Lightbox

Відкривається кліком по кадру: великий перегляд, статус із причиною, розмір і вага, папка та підпис (у режимі Select — лише для читання).

- **←** і **→** переходять між кадрами в порядку відфільтрованої сітки; **Esc** або **Close** закривають, фокус переходить на кадр, показаний останнім. Клавіші під оверлеєм не рухають курсор сітки.
- **Pin / Unpin**, **Ban / Unban / Remove from dataset**, **Return to inbox** — ті самі дії; **P** і **B** працюють і тут.
- **Rename file** (inline: Enter підтверджує, Escape скасовує) і **Delete file** доступні лише для кадрів `inbox/`; шлях, посилання й TXT оновлюються разом із файлом.
- **Edit in Photopea** відкриває кадр на весь екран у Photopea. **Ctrl/Cmd + S** тоді зберігає документ, а не проєкт; успішне збереження закриває оверлей і оновлює прев’ю, закриття з незбереженими змінами питає підтвердження. Photopea має власні комбінації клавіш усередині iframe. **Esc** закриває лише оверлей, не lightbox під ним. Дочекайтеся завершення запису перед зміною проєкту.

### Health

Права колонка пояснює, наскільки різноманітний і готовий до експорту Dataset. Поки Assemble не виконувався, вона лише описує, що покаже, бо ознаки зображень рахуються після першого Assemble.

- **Effective size** — «N images ≈ M distinct»: скільки «ефективно різних» зображень у наборі (метрика Vendi). Без моделі DINOv2 панель показує запит на завантаження замість вигаданого числа.
- **Required checks** — обов’язкові перевірки: кількість файлів, роздільність, майже-дублікати, підписи, trigger word, технічна якість. Кожна позначена **OK / Check / Fix** чи «не оцінено». Готовність — найгірший статус серед обов’язкових; загального балу немає.
- **Coverage** — осі покриття за типом проєкту із стовпчиками «кількість / рекомендована».
- **What to do next** — підказки з поясненнями, звідки взято числа; частина має кнопку дії.
- **Saturation** — чи додавання останніх зображень ще збільшувало покриття.
- **Фільтр за кліком.** Перевірка, смуга покриття чи підказка, що має перелік кадрів, натиснута фільтрує сітку цими кадрами; позначка «Showing: …» з хрестиком знімає фільтр. Дія «позначити повтори» лише показує кадри, нічого не видаляє. Дія «прибрати з підписів» (для постійних рис) працює через сервіс змін підписів: перед застосуванням з’являється підтвердження, зміна — один крок Undo, файли без збережених тегів пропускаються.

Профільні осі покриття залежать від типу проєкту: General — орієнтація та фон; Character — кадрування, орієнтація, фон, освітлення; Style — суб’єкт, пропорції (бакети цільової моделі), фон; Concept — фон, кадрування, орієнтація. Осі зі змістом із тегів беруть їх зі збережених тегів або, якщо тегів немає, із тексту підпису; орієнтація й пропорції — з розмірів файлів. Вісь не оцінюється, якщо файлів менше 8 або ознаку осі має менше половини файлів; панель пише причину. Частки та пороги евристичні (`thresholds.ts`). Осі не впливають на готовність. Політика тегів залежить від типу: Character і Concept вимагають trigger word і пропонують прибрати теги, що є майже в усіх файлах; Style такі теги лишає (вони описують стиль); General лише пропонує переглянути.

Моделі зберігаються в браузері; застосунок один раз за сесію просить браузер не витісняти їх. DINOv2 не завантажується мовчки: потрібне підтвердження. Ознаки зображень кешуються в IndexedDB, тож повторний запуск не перераховує вже оброблені файли; якщо модель не завантажується, запуск зупиняється з помилкою, а не продовжує з частковими даними. Метрики на основі зображень (майже-дублікати, Effective size, Coverage, Saturation, Consistency) потребують ознак DINOv2; без неї вони не оцінені. Звіт описує файли, а не передбачає якість навченої LoRA, а пороги DINOv2-метрик евристичні й не відкалібровані на реальних наборах.

## Caption mode

Перемикач **Caption** показує лише кадри `dataset/` картками з тегами. Картка без файлу підпису має позначку «no caption», з порожнім — «empty caption». Клік відкриває lightbox із редагованим підписом (**Save caption**, **Ctrl/Cmd + Enter**; незбережена чернетка зберігається при переході стрілками). Ctrl/Cmd + клік вибирає картку, Shift + клік — діапазон.

Панель угорі:

- **Trigger word** застосовується на Enter або при втраті фокусу: застосунок переписує TXT усіх кадрів `dataset/` одним кроком Undo.
- **Add tag to selected** додає тег до вибраних карток; **Remove tag** вилучає тег із вибраних, а якщо вибору немає — з усіх підписів Dataset (кадри без підпису не чіпаються). Збіг ігнорує регістр; кожна групова зміна — один крок Undo.
- **Auto-caption N images** описує кадри локальною моделлю й записує пропозиції. Типово **не перезаписує**: бере лише кадри без підпису (немає TXT або він порожній), trigger word не потрапляє в теги. Прапорець **overwrite existing** розширює дію на всі кадри. Кнопка **Apply N suggestions** з’являється, коли є готові пропозиції; запис — один крок Undo. Без підключеної моделі кнопка недоступна, а панель пропонує підключити її (див. «Settings»). Риси персонажа застосовуються до пропозицій під час показу й запису.
- Справа — **Tags**: частоти тегів «файлів / усього»; клік по тегу підставляє його в поле **Remove tag**. Блок **Profile advice** з’являється, коли тег майже в усіх підписах: для Character радить прибрати постійні риси (кнопка **Remove constant traits**), щоб модель прив’язала їх до trigger word, а не до підписів; для інших типів лише радить перевірити.

Порожній підпис є навмисним значенням: очищення tags не повертає старий текст. Підпис зберігається в `<ім’я>.txt` поруч із зображенням (у `dataset/` — з trigger word першим); окремих метаданих підпису немає.

### Локальна модель підписів

Для автотегера виберіть `model.onnx` і `selected_tags.csv` сумісного WD/Danbooru-формату (Settings → Caption model). Обчислення виконує ONNX Runtime Web. Або натисніть кнопку завантаження WD ViT Tagger v3 (≈378.8 MB, Apache-2.0): завантаження починається лише за кнопкою, показує прогрес, його можна скасувати (нічого не зберігається) або повторити; файли перевіряються за SHA-256, зберігаються в браузері й після успіху тегер підключається автоматично. Модель завантажується й виконується в окремому воркері, що стартує ліниво; при збої WebGPU воркер переходить на WASM. Ручний вибір файлів лишається доступним і перезаписує завантажену модель; після перезапуску може знадобитися кнопка **Reconnect** або повторний дозвіл. Автоматичні теги варто переглянути й відредагувати.

## Експорт

Кнопка **Export N pairs** у шапці відкриває діалог. Експортується лише Dataset (`dataset/`).

1. **Checks** — обов’язкові перевірки зі звіту якості Health; **Warnings** — осі покриття з зауваженнями й попередження плану (одним рядком — кількість файлів без `.txt`). Перевірки й попередження ніколи не блокують експорт.
2. **Format**: **ZIP in project (exports/)** (типово; `exports/<назва>-<дата>.zip`, існуючі архіви не перезаписуються), **ZIP download** або **Folder** (порожня папка; конфлікт імені припиняє операцію до запису; після запису **Show** перелічує файли).
3. **Resize copies**: **Original size** (типово), **Longest side** (поле «Pixels») або **buckets** цільової моделі. Зменшуються лише експортовані копії, ніколи не збільшуються; зображення проєкту лишаються як є. Лише PNG, JPEG, WebP.
4. **Export N pairs** запускає запис з прогресом і **Cancel**; скасування не прибирає вже записані файли. Під час роботи Escape не закриває діалог.

Експорт — побайтова копія `dataset/` з усіма підпапками: зображення зберігають формат, TXT копіюється як є (trigger word уже в ньому), PSD перетворюється на PNG через Photopea. Зображення без `.txt` експортується без нього. Відео не експортується — спершу збережіть кадри. Після успіху сесія запам’ятовує `lastExport`.

## Відеокадри

Відео, імпортоване в Sources, перелічене під деревом папок і не вважається кадром. Клік по відео відкриває **Video Frames** на весь екран; відео, перетягнуте на Sources, відкриває його ж після імпорту. Можна вручну зберегти поточний кадр або завантажити модель для автоматичного відбору. Fast аналізує вибірку, Full — кожен декодований кадр. Короткі моменти можуть бути пропущені у Fast; Full потребує більше часу.

Кадри зберігаються за замовчуванням у `inbox/<назва відео>/` і після збереження індексуються, тож з’являються в Sources та сітці як Inbox. Збереження не додає кадри до Dataset: далі вони проходять Assemble або Pin. **Esc** і **Close** закривають оверлей; якщо виконується відеоопція, потрібне підтвердження. Підтримка декодування залежить від кодеків браузера. [Докладніше про Video Frames](video-frames.md).

## Settings і Project settings

**Settings** (кнопка в шапці, команда або екран Projects) — налаштування застосунку:

- **Theme** (System / Light / Dark) і **Keyboard shortcuts** (відкриває довідник скорочень).
- **Similarity strictness (this project)** — те саме налаштування, що Strictness в Assemble; показується лише при відкритому проєкті.
- **Caption model** — стан, вибір `model.onnx` і `selected_tags.csv`, завантаження WD ViT Tagger v3, **Reconnect**.
- **Image features model (DINOv2)** — чи завантажена модель.

**Project settings** (клік по чіпу «тип · модель» або команда **Project settings**):

- **Type** і **Model**: зміна одразу оновлює чіп і мінімальну коротшу сторону. Нова модель змінює правило розміру: пропозиції якості, що були лише пропозиціями (без ручного рішення), скидаються, а результат Assemble обнуляється; рішення користувача (Pin, Ban) лишаються.
- **Character traits** — лише для типу Character: перелічіть типові риси (наприклад `blue_eyes`, `long_hair`) і для кожної оберіть **Always tag** (тег завжди додається до пропозицій тегера) або **Leave to trigger** (тег не пишеться, щоб його вивчив trigger word). В обох режимах прибираються суперечливі варіанти тієї самої групи (інший колір очей, волосся тощо). Модельні теги зберігаються сирими, правила застосовуються під час показу пропозицій і запису; уже написані вручну підписи не змінюються. Для інших типів блок прихований, а список зберігається.
- **Output transform** — застосовується до зображень, коли їх приймають у Dataset: **None (original images)** (типово), **Fit within 512**, **Center crop 512**, **Center crop 768**. Збережений нестандартний варіант (старі проєкти) показується як **Custom** і не перезаписується, доки ви не оберете інший. Вибір **None** прибирає перетворення.

## Versions, перейменування, Activity і палітра команд

- **Versions** (кнопка в шапці або команда **Project versions**): поле **Version name** і **Save version** створюють знімок файлів проєкту; **Restore** (після підтвердження) замінює поточний стан обраним знімком. Знімок не включає службові теки, `exports/` і `.git`; відновлення змінює файли проєкту, тож не плутайте його з Undo.
- **Перейменування проєкту**: клік по назві в шапці або команда **Rename project**; запитується нова назва, також оновлюється Recent.
- **Activity** (рядок статусу внизу або команда **Activity**): журнал імпортів, аналізу, експорту й інших операцій (до 1000 записів, є **Clear**). Він показує стан тривалих дій.
- **Командна палітра** — **Ctrl/Cmd + K**; **?** (поза текстовими полями) відкриває довідник скорочень. Команди: Undo, Redo, Save project, New project, Open project, Settings, Rename project, Project versions, Project settings, Activity, Keyboard shortcuts, Theme. Перемикач **Single-key shortcuts** вимикає одноклавішні скорочення.

| Дія | Комбінація |
| --- | --- |
| Командна палітра | Ctrl/Cmd + K |
| Довідник скорочень | ? |
| Undo / Redo | Ctrl/Cmd + Z / Ctrl/Cmd + Shift + Z |
| Збереження проєкту | Ctrl/Cmd + S |
| Pin / Ban вибраних кадрів або кадру під курсором | P / B |
| Перехід між кадрами (сітка, lightbox) | стрілки; у сітці також Home / End |
| Зберегти підпис у lightbox | Ctrl/Cmd + Enter |
| Закрити lightbox або оверлей | Esc |

Перепризначення скорочень не підтримується. Undo/Redo діють для підтримуваних дій: Assemble, Pin, Ban, Clear override, Return to inbox, групові зміни підписів, зміна trigger word.

## Якщо щось не працює

| Симптом | Що перевірити |
| --- | --- |
| Немає доступу до папки | Підтримку File System Access, HTTPS/localhost, дозволи та повторне відкриття папки (у Recent — стан **Needs access**) |
| Помилка збереження | Права запису, доступність диска, вільне місце; після виправлення повторіть запис |
| Assemble недоступний | Чи позначено папку в Sources і чи в ній є зображення |
| Health порожній | Він заповнюється після першого Assemble; без моделі DINOv2 запропонує завантаження |
| Немає PSD-прев’ю або конвертації | Чи завантажився Photopea та чи завершена попередня операція |
| Не працює Auto-caption | Чи підключено модель (Settings → Caption model), сумісність ONNX/CSV і дозволи читання |
| Відео не декодується | Підтримку конкретного кодека браузером, а не лише розширення |
| Закінчилося місце відеокешу | Очистіть відеокеш; це прибере кадри й аналізи, але лишить завантажену модель і кеш ознак зображень, не торкаючись файлів проєкту |
| Експорт повідомляє про конфлікт | Оберіть порожню вихідну папку |
| Проєкт не відкривається після старої міграції | Оберіть Open without upgrading, розв’яжіть зазначені проблеми й відкрийте проєкт знову |
| Після очищення браузера зник стан | Повторно відкрийте папку; браузерні кеші не є резервною копією проєкту; Recent-список відновіть через **Open folder…** |

# Посібник користувача

## Створення та відкриття проєкту

Запустіть застосунок за [інструкцією встановлення](../README.md). Для роботи з локальною папкою браузер має підтримувати File System Access API. Якщо вибір папки недоступний, перевірте браузер і те, що застосунок відкритий через localhost або HTTPS.

Створіть або відкрийте папку проєкту через **File** (New Project Directory, Open Project Directory). Інтерфейс повністю англійською; оболонка має лише меню **File**, **View** і **Tools**: панелі Explorer, Inspector і Output відкриває **View**, Versions — **File**, а **File → Project home** повертає на домашній екран проєкту. Новий проєкт потребує назви, типу (General — за замовчуванням, Character, Style або Concept) і цільової моделі (SD 1.5, SDXL, Flux). Тип задає початкові налаштування, пояснення та набір осей покриття у звіті якості; набір інструментів однаковий. Тип і модель можна змінити в шапці Build (списки Type і Model). Старий проєкт без типу відкривається як General без запитів і без переписування файлу; модель для нього визначається автоматично (див. модель даних).

### Структура папки

Деталі — у [моделі даних](data-model.md). Коротко: сирі матеріали лежать у `inbox/` (похідні — в `inbox/edits/`), у `dataset/` — лише пари зображення + `<ім’я>.txt` (підпапки на кшталт `10_name/` дозволені), `exports/` містить ZIP експорту, а службові дані — `.datasetcreator/`. Вміст `dataset/` готовий для kohya або OneTrainer без перетворень. Підпис — це TXT: немає файлу — підпису немає, порожній файл — порожній підпис; у `dataset/` TXT починається з trigger word.

Якщо відкрити папку без проєкту, застосунок попросить підтвердження перед створенням проєкту. Файли, перейменовані чи переміщені поза застосунком, розпізнаються за вмістом (SHA-256); зовнішня зміна вмісту робить уже прийняте рішення Build застарілим (stale) — його треба підтвердити знову. Справжній Git-репозиторій у папці захищено від змін.

### Старі проєкти

Проєкт старого формату (v2/v1) відкривається через діалог **Upgrade project layout** із переліком змін. Перед змінами записується знімок версії, замінені файли копіюються в `.datasetcreator/backup`, а перервана міграція продовжується при наступному відкритті. Якщо оновлення заблоковано незавершеною старою міграцією, діалог пропонує **Open without upgrading**: проєкт відкриється у старому вигляді, а оновлення запропонують знову пізніше.

Статус у нижній частині робочого простору відрізняє тимчасову сесію від збереження в папку. Якщо папку не підключено, не вважайте дані на диску збереженими. Помилка автозбереження потребує повторної спроби після відновлення доступу.

## Build: основний шлях

Після відкриття проєкту застосунок показує **Project home**: назву, тип і модель, кнопку «Continue: <етап>», п’ять етапів із лічильниками, чекліст «Getting started» і список Advanced-інструментів. Звідти (і з **Tools → Build Dataset**) відкривається **Build Dataset** — основний шлях від матеріалів до експорту. Угорі Build є степер етапів **Add → Select → Caption → Check → Export**; кожен етап показує лічильник і стан (Not started / In progress / Done), а кнопка «Next: …» унизу веде далі.

Інші інструменти зібрано в **Tools → Advanced**: Import, Video Frames, Similar images (пошук дублікатів), Photopea, Similarity map (аналіз зв’язків), Browse files (перегляд зображень, PSD і відео), Caption, Export.

- **Add** — налаштування проєкту (Type, Model) та Import: файли потрапляють у `inbox/`.
- **Select** — черга кандидатів; перемикач **List / Grid / Clusters**.
- **Caption** — підписи членів `dataset/`.
- **Check** — звіт якості Dataset.
- **Export** — експорт лише Dataset.

### Select

Якщо ввімкнено «Auto pipeline» (у згортці **Settings**), автоматично виконується лише швидкий тріаж якості кожного зображення. Добір кандидатів і підписи запускаються явно: кнопка **Suggest selection** відкриває діалог Auto-select, а **Prepare caption suggestions** (для всього Dataset або вибраних елементів) готує пропозиції тегів локальним тегером, якщо його підключено. Клавіатурний фокус лишається на корені Build, тож A / X / J / K працюють і після зникнення сфокусованого елемента. Результат тріажу розкладається на групи:

- **Rejected** — точний дублікат, замалий розмір, розмите або майже чорне зображення, майже-дублікат чи «не потрапило до добору»;
- **Accepted** — перевірки пройдено або зображення вибрано автодобором;
- **Flagged** — сумнівні випадки (недостатня роздільність, м’яка різкість, недо-/переекспонування), відео та файли, які не вдалося виміряти. Зображення, що вже лежить у Dataset, ніколи не пропонується до тихого відкидання — воно потрапляє у Flagged.

Зображення без рішення й без аналізу мають стан **Undecided**. Групи є лише пропозиціями: ваше ручне рішення завжди переважає. Фільтр черги дозволяє показати кожну групу, а «Accept all» / «Reject all» застосовує рішення до групи. Згортка **Settings** містить Review, Output, Model, Auto pipeline і Trigger word; Target і кнопка **Auto-select** (діалог автоматичного формування Dataset) лишаються на панелі. Список **Model** (SD 1.5 — 512 px, SDXL і Flux — 1024 px) задає мінімальну коротшу сторону для перевірок тріажу й для звіту якості. Trigger word застосовується на Enter або при виході з поля й перезаписує TXT усіх файлів у `dataset/` одним кроком, який скасовує Undo.

**Grid** показує кандидатів мініатюрами з бейджами Accepted / Rejected / Undecided / Flagged. Клік вибирає, Shift або Ctrl/Cmd — кілька; стрілки рухають курсор, Space перемикає вибір, Enter або подвійний клік відкриває елемент у List, A приймає, X відхиляє вибране (або поточне), якщо вибору немає. Масове рішення — один крок історії; воно оновлює шляхи й реєстр ресурсів одним пакетом, а не окремо для кожного файлу.

### Auto-select у два проходи

У Build Auto-select працює у два проходи; жоден із них не переміщує файли, доки ви не застосуєте результат.

1. **Shortlist.** Діалог (Target — загальна кількість у Dataset) має прапорці **Include folders** для вибору папок кандидатів. Він порівнює зображення за DINOv2 і позначає візуально різноманітний шорт-лист приблизно в 1,75 раза більший за потрібну кількість: кластери за k-medoids отримують квоти, а зображення, надто схожі на Dataset чи на вже вибране (поріг 0,93 за DINOv2), відкидаються як майже-дублікати. Дублікати визначаються лише за виглядом, ніколи за іменем файлу чи ідентифікатором допису. Файли, які не вдалося прочитати, пропускаються й перелічені зі причинами в списку skipped files; PSD кодуються з наявних прев’ю. Поля «What should this Dataset cover?» немає. Результат — позначка **Shortlisted** у черзі, фільтр Shortlisted і панель шорт-листа над чергою.
2. **Narrow to N.** Спершу підготуйте пропозиції підписів для шорт-листа (**Prepare caption suggestions**). Звуження обирає N зображень за покриттям тегів із вагою IDF і візуальним приростом різноманітності; trigger word, риси персонажа та теги, присутні майже в усіх (≥90 %) зображеннях шорт-листа, ігноруються. **Apply** додає вибране до Dataset одним пакетом і одним кроком Undo.

Pass 1 можна повторити після зміни папок чи цілі; панель шорт-листа дозволяє його скасувати. Зміна вмісту зображення вилучає його із шорт-листа.

### Перегляд кластерами

Перемикач **List / Grid / Clusters** над чергою в режимі Clusters показує кандидатів групами. Є два види: **майже-дублікати** (практично однакові кадри) і **тематичні кластери** (схожий предмет чи сцена). Пороги ті самі, що й у Strictness та рівнях схожості: майже-дублікати відповідають рівню Strict (Near copy), тематичні кластери — поточному Strictness. Окремих налаштувань немає.

Кластери за зображеннями потребують DINOv2 (Build сам не завантажує модель мовчки: показує запит «Download DINOv2 (~88 MB)?»). У режимі histogram показуються лише точні дублікати (збіг SHA-256) і пропозиція завантажити DINOv2 для тематичних груп. Для DINOv2 під заголовком є рядок про майже-дублікати: скільки груп, скільки зайвих і як змінився б effective size (Vendi), якщо лишити по одному зображенню з групи.

Дії над кластером (кожна — одна операція в історії, її можна скасувати разом):

- **Accept all** і **Reject all** — застосовують рішення до всіх членів за тими самими правилами, що й дії над групою черги;
- **Keep best** — лишає одне найкраще зображення, решту відхиляє. Вибір: без reject-рівня прапорів якості, далі різкість, коротша сторона, наявність у Dataset, порядок у сесії; зображення без виміру — останні;
- **Expand** — показує членів; **Open in list** повертає до елемента в списку.

Клавіші: J / K — наступний або попередній кластер, A — Accept all, X — Reject all, B — Keep best, Enter — розгорнути чи згорнути.

### Звіт якості Dataset

Звіт показано на етапі **Check**; у Similarity map він показаний рядком «Dataset readiness».

Звіт складається з двох частин. Обов’язкові перевірки: кількість файлів, роздільність, майже-дублікати, підписи, trigger word і технічна якість. Готовність — найгірший статус серед обов’язкових перевірок (Готово / Є зауваження / Не готово); загального балу немає. Пояснювальні метрики не впливають на готовність:

| Метрика | Що показує |
| --- | --- |
| Effective size (Vendi) | скільки «ефективно різних» зображень у наборі порівняно з кількістю файлів |
| Coverage | яку частку матеріалів (кандидатів) покривають вибрані зображення |
| Saturation | чи додавання останніх зображень ще збільшувало покриття |
| Часті та рідкісні теги | теги майже в усіх файлах або лише в одному |
| Довжина підписів | медіана токенів і підписи, довші за ≈70 токенів (ліміт CLIP) |
| Consistency | зображення-викиди відносно центру набору |

Профільні осі покриття залежать від типу проєкту: General — орієнтація та фон; Character — кадрування, орієнтація, фон, освітлення; Style — суб’єкт, пропорції (бакети цільової моделі), фон; Concept — фон, кадрування, орієнтація. Осі зі змістом із тегів (кадрування, фон, освітлення, суб’єкт) беруть їх зі збережених тегів або, якщо тегів немає, із тексту підпису; орієнтація й пропорції — з розмірів файлів. Вісь не оцінюється, якщо файлів менше 8 або ознаку осі має менше половини файлів; панель пише причину. Рекомендована кількість для групи — `ceil(частка × max(кількість файлів, мінімум цілі))`; частки та пороги евристичні й лежать у `thresholds.ts` (`profileCoverage`). Осі не впливають на готовність.

Політика тегів залежить від типу: Character і Concept вимагають тригер-слово й пропонують прибрати теги, що є майже в усіх файлах («Прибрати з підписів»); Style такі теги лишає (вони описують стиль); General лише пропонує переглянути. Дія видалення працює через сервіс змін підписів: перед застосуванням з’являється підтвердження, зміна — один крок історії (скасовується Undo), файли без збережених тегів пропускаються. Підказки про прогалини («Бракує кадрів…», групи майже-дублікатів із діями «Позначити повтори», відсутній тригер) мають пояснення, звідки взято числа. «Позначити повтори» лише виділяє перший файл групи, нічого не видаляє.

Моделі зберігаються в браузері; застосунок один раз за сесію просить браузер не витісняти їх (`navigator.storage.persist`). DINOv2 не завантажується мовчки: потрібне підтвердження. Хеш збереженої моделі перевіряється один раз за сесію. DINOv2 працює у воркері, що стартує ліниво, а ознаки зображень зберігаються в постійному кеші в IndexedDB, тож повторний запуск не перераховує вже оброблені файли. Якщо модель не завантажується, запуск зупиняється з помилкою, а не продовжує з частковими даними.

Метрики на основі зображень (майже-дублікати, Effective size, Coverage, Saturation, Consistency) потребують ознак DINOv2. Без завантаженої моделі панель показує кнопку «Download DINOv2 (≈88 MB)», а ці метрики позначаються як не оцінені. Звіт описує файли, а не передбачає якість навченої LoRA. Пороги для DINOv2-метрик (майже-дублікат, покриття, Vendi) евристичні й не відкалібровані на реальних наборах даних; сприймайте їх як підказки.

## Імпорт і відбір

Import приймає локальні файли, папки, перетягування та ZIP. Підтримуються зображення BMP/GIF/JPEG/PNG/WebP, PSD, відео MP4/WebM, TXT і JSON. Підписи TXT зіставляються із зображеннями за базовим ім’ям у межах папки й залишаються поруч із ними як `<ім’я>.txt`. Однакові імена в різних папках не є однією парою. Зображення декодуються у воркері, а нові файли додаються до проєкту й зберігаються пакетами (до 25 файлів або 250 мс), тому великий імпорт не оновлює інтерфейс після кожного файлу.

Explorer показує файли проєкту (разом із `exports/`, яка не індексується). Similar images допомагає знайти схожі вихідні зображення, Similarity map — дослідити зв’язки, Browse files — переглянути зображення, PSD та відео. Подібність є підказкою для відбору, а не гарантією дублювання чи якості даних.

Similar images і Similarity map використовують один повзунок **Strictness** (Strict / Balanced / Loose). Він відповідає рівням схожості DINOv2: Duplicate (той самий файл або його копія), Near copy, Similar і Related; Strict групує до Near copy, Balanced — до Similar, Loose — до Related. Без завантаженої DINOv2 (≈88 MB) застосовується запасний варіант за гістограмою яскравості з власними порогами; він грубіший. Поріг Near copy спільний для автодобору, тріажу в Build і звіту якості.

Відкрийте зображення або PSD у Photopea для редагування. Save записує зміни документа; Save copy створює копію. Дочекайтеся завершення запису перед зміною проєкту. Photopea має власні комбінації клавіш усередині iframe.

## Dataset

Dataset один на проєкт і відповідає фізичній папці `dataset/`.

- **Add to Dataset** переміщує вибрані ресурси до цієї папки; для ресурсу лише в пам’яті створюється файл.
- **Remove from Dataset** переміщує їх в `inbox/`, зберігаючи матеріали в проєкті.
- Переміщення через межу `dataset/` разом із зображенням переносить його TXT: усередину — trigger word додається на початок, назовні — прибирається.
- Підтримувані зміни можна скасувати через Undo/Redo. Не плутайте вилучення з Dataset із видаленням файлу в Explorer.
- Не потрібно створювати окремі `*.dataset.json` або sidecar `*.manifest.json`: це попередні формати, їх обробляє міграція.

Діалог формування Dataset аналізує спільні кандидати й поточний набір, дозволяє задати ціль, переглянути пропозиції та закріпити або виключити кандидати. У Build він працює у два проходи (див. «Auto-select у два проходи»). Перевіряйте результат перед застосуванням. Coverage показує покриття множини кандидатів за ознаками, а не очікувану якість навченої моделі.

## Підписи

На етапі **Caption** у Build показано членів `dataset/`; без підпису — першими. J / K — наступний або попередній елемент, Ctrl/Cmd + Enter — зберегти й перейти до наступного без підпису; Shift або Ctrl/Cmd + клік вибирає кілька елементів для **Add tag to selected** / **Remove tag from selected** (один крок Undo). Якщо TXT не починається з trigger word, з’являється попередження з кнопкою **Add trigger**. В Advanced-інструменті Caption можна редагувати один підпис або застосувати групову зміну. Групова дія працює з вибраними файлами, а якщо вибору немає — з відфільтрованими. Перевіряйте фільтр перед застосуванням.

Для локального автотегера виберіть `model.onnx` і `selected_tags.csv` сумісного WD/Danbooru-формату. Обчислення виконує ONNX Runtime Web. Замість цього в Build або Settings можна натиснути кнопку завантаження WD ViT Tagger v3 (≈378.8 MB, Apache-2.0): завантаження починається лише за кнопкою, показує прогрес, його можна скасувати (нічого не зберігається) або повторити; файли перевіряються за SHA-256, зберігаються в браузері й після успіху тегер підключається автоматично. Інференс тегера виконується у воркері, що стартує ліниво. Ручний вибір файлів лишається доступним і перезаписує завантажену модель. Після перезапуску може знадобитися знову надати доступ до файлів моделі. Автоматичні теги варто переглянути й відредагувати.

### Риси персонажа

Для проєкту типу «Character» у Build (Add → Project settings і Select → Settings) є блок **Character traits**. Перелічіть типові риси персонажа (наприклад `blue_eyes`, `long_hair`, `red_hair`) і для кожної оберіть режим: **Always tag** — тег завжди додається до пропозицій тегера; **Leave to trigger** — тег не пишеться, щоб його вивчив trigger word. В обох режимах тегер прибирає суперечливі варіанти тієї самої групи (інший колір очей, колір чи довжину волосся тощо). Модельні теги зберігаються сирими, а правила застосовуються під час показу пропозицій у Build, під час злиття та в інструменті Caption; уже написані вручну підписи не змінюються. Звіт якості не радить прибирати перелічені риси як постійні теги. Для інших типів проєкту блок прихований, а список зберігається.

Порожній підпис є навмисним значенням. Очищення tags не повинно автоматично повертати старий текст. Підпис зберігається в `<ім’я>.txt` поруч із зображенням (у `dataset/` — з trigger word першим); окремих метаданих підпису немає.

## Відеокадри

Відкрийте Video Frames або відповідну дію для MP4/WebM в Explorer. Можна вручну зберегти поточний кадр або завантажити модель для автоматичного відбору. Fast аналізує вибірку, Full — кожен декодований кадр. Короткі моменти можуть бути пропущені у Fast; Full потребує більше часу.

Перегляньте запропоновані кадри, виберіть папку призначення і збережіть PNG. Збереження у звичайну папку не додає кадри до Dataset: використайте окрему дію додавання. Підтримка декодування залежить від кодеків браузера. [Докладніше про Video Frames](video-frames.md).

## Експорт

На етапі **Export** у Build джерело зафіксоване як Dataset; в Advanced-інструменті Export можна вибрати також workspace.

1. Перегляньте файли плану й попередження (зображення без `.txt` експортується без нього).
2. Оберіть призначення. ZIP за замовчуванням зберігається в `exports/<назва>-<дата>.zip` (існуючі архіви не перезаписуються); також можна завантажити ZIP або записати у порожню папку: конфлікт імені припиняє операцію до запису.

Експорт Dataset — побайтова копія `dataset/` з усіма підпапками: зображення зберігають формат, TXT копіюється як є (trigger word уже в ньому), PSD перетворюється на PNG. Відео не експортується — спочатку збережіть кадри. Скасування не прибирає файли, які вже успішно записані.

## Навігація й збереження

| Дія | Стандартна комбінація |
| --- | --- |
| Командна палітра | Ctrl/Cmd + K |
| Налаштування скорочень | ? |
| Збереження активного документа або проєкту | Ctrl/Cmd + S |
| Пошук у галереї | / |
| Вибір елемента | Space |
| Діапазон вибору | Shift + стрілки |
| Вибрати всі відфільтровані | Ctrl/Cmd + A |
| Зберегти підпис і перейти далі | Ctrl/Cmd + Enter |

Команди залежать від активної панелі; текстові поля зберігають звичайну поведінку введення. Скорочення можна змінювати в налаштуваннях.

Вкладки можна переносити між групами, панелі — докувати або робити плаваючими. Геометрія зберігається локально. Operations показує стан тривалих дій і дозволяє скасування там, де воно підтримується. Versions (File → Versions) створює знімки проєкту; відновлення версії змінює поточні файли.

## Якщо щось не працює

| Симптом | Що перевірити |
| --- | --- |
| Немає доступу до папки | Підтримку File System Access, HTTPS/localhost, дозволи та повторне відкриття папки |
| Помилка збереження | Права запису, доступність диска, вільне місце; після виправлення повторіть запис |
| Немає PSD-прев’ю або конвертації | Чи завантажився Photopea та чи завершена попередня операція |
| Не працює автотегер | Вибрані ONNX/CSV-файли, сумісність моделі та дозволи читання |
| Відео не декодується | Підтримку конкретного кодека браузером, а не лише розширення |
| Закінчилося місце відеокешу | Очистіть відеокеш; це прибере кадри й аналізи, але лишить завантажену модель і кеш ознак зображень, не торкаючись файлів проєкту |
| Експорт повідомляє про конфлікт | Оберіть порожню вихідну папку |
| Проєкт не відкривається після старої міграції | Оберіть Open without upgrading, розв’яжіть зазначені проблеми й відкрийте проєкт знову |
| Після очищення браузера зник стан | Повторно відкрийте папку; браузерні кеші та layout не є резервною копією проєкту |
